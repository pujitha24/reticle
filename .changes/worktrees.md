### Fixed

- **`@reticlehq/server` — an agent in one git worktree could drive another worktree's tab.** Every worktree of a project declares the same project id. So a call with no `sessionId` from an agent in worktree A could land on the tab that worktree B serves, and act on code that agent never changed. Calls with no `sessionId` now reach only the tabs that the agent's own worktree serves. When every tab comes from another worktree, Reticle refuses and names those tabs, their folders and their branches. An explicit `sessionId` still reaches any tab. This also works for the worktrees of a bare clone.
- **`@reticlehq/server` — work done in a worktree was saved in the main checkout.** Intents, flows and runs from a page that a worktree served went to the main checkout's `.reticle/`. So the worktree's pull request did not carry its flows, and `reticle gate` in the worktree saw nothing covered. They now go to the worktree that served the page.
- **`@reticlehq/server` — a new worktree started with no link and no memory.** `.reticle/` is often git-ignored, so `git worktree add` copies no `cloud.json` and no flow that is not committed yet. A new worktree now uses the main checkout's cloud link, and replays the main checkout's flows when it has none of its own. It saves new flows in the worktree.
- **`@reticlehq/server`, `@reticlehq/vite-plugin` — a worktree with no `.reticle.json` became a second project.** When `.reticle.json` is git-ignored or not committed, the worktree now reads the main checkout's project id and port. Before, it got a new id and a second daemon.
- **`@reticlehq/core`, `@reticlehq/browser` — pages on a `.localhost` name could not connect.** A dev proxy such as portless serves each app and each worktree at `https://<branch>.<app>.localhost`. The SDK read those pages as remote and did not start, and the bridge refused them. RFC 6761 reserves every `.localhost` name for loopback, so Reticle now accepts them. The Vite plugin also announces the proxy URL, so the daemon can tell which worktree served the page.

### Added

- **`@reticlehq/server` — the session list names each tab's worktree.** A tab that a linked git worktree serves carries `worktree`, with the folder and the branch, so an agent can see which code each tab runs.
- **`pnpm gate:worktrees`.** Two agents in two git worktrees of one app, one real daemon. Each agent must reach only its own tab.
